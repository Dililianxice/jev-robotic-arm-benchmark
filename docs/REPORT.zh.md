# Jev × 频繁小步机械臂决策：第三轮配对实验

本报告由本地记录生成。物理、提示条件和新 API 实验在观察新模型结果前冻结；未在测试结果上调整模型、动作、场景或判据。

## 先说结论

Jev 成功 3/3，DeepSeek 成功 0/3，规则成功 3/3。
预先规定的探索性优势门槛：**达到**。该门槛用于决定是否值得扩展，不是统计显著性或通用机器人能力证明。
本轮达到的是成功数差异分支，不是双方成功后比较完成速度的分支；DeepSeek 未完成，不能说 Jev 成功完成任务快了多少倍。

这里问的是：给定同一套明确的条件策略，模型每步选择一次意图，再选择方向和夹爪，谁更可靠、更省时？它与上一轮仅解释高层任务的比较不同。成功率只对应同一个苹果入盘任务的三个微小初始位置变化。

## Jev 在机械臂里具体做什么

1. 接收当前末端/物体坐标、接触、对齐、抓稳情况等结构化状态。当前 Jev 为文本输入模型；本实验不让它直接看相机、读取关节电流或解码脑信号。
2. 在 approach、grasp、lift、carry、lower、release、withdraw、finish 中选择下一步意图。
3. 根据所选意图，同一请求分别判断 X/Y/Z 应正向、保持还是反向，以及夹爪应开、保持还是闭。它返回的概率分布在本轮不参与额外筛选。
4. 程序决定毫米级位移幅度，做逆运动学、限位和关节伺服；MuJoCo 决定真实接触和物体运动。没有把完整抓取技能藏在单个动作内，也没有由模型直接生成关节力矩。

这是一种把自然语言策略变成反馈决策的接口。可取之处可能是较低的调用开销和易组合的结构化选择；本任务并没有证明这些明确数值规则必须用 AI。

- 每个模型共享完全相同的问题生成器、候选动作和观测格式。API 调用需要输入当前各自真实轨迹状态；因此整局中两模型输入不一定相同，这也是额外做固定状态探针的原因。

- 原公开 Jev 113步轨迹已在本机复现：最大 qpos 误差为 5.53×10⁻¹⁰ 以下，小于 10⁻⁷ 容差。

## 费用、可信度与限制

- Jev 按官方每百万输入 token $0.042，输出免费。DeepSeek 使用实际返回的缓存命中/未命中及输出 token，给非高峰/高峰价格界限。是公开单价估算，不是账户账单；计价快照来自当日 v2 已核对资料。失败无 usage 的费用无法确认，不按免费解释。
- [TypeSafe 模型说明与计价](https://docs.typesafe.ai/models)；[DeepSeek 官方计价](https://api-docs.deepseek.com/quick_start/pricing/)。
- 三个初始位置重复不是三种任务，更不是足够大样本；不把几百次相关请求当成几百个独立机器人试验，不计算夸大的显著性。
- 精确状态和提示里已写好的抓取顺序显著降低难度。规则也成功说明这个任务能被程序覆盖，不说明真实机器人智能已被测透。
- 暂停物理不能评估移动目标、外力、滑落时的实时反应；不代表 UR10 实机可直接运行。
- 只有一个物体形状、一种目标、轻微位置变化；没有遮挡/视觉误差/新物体/复杂接触。
- 本轮没有人参与闭环，也没有神经信号，不能声称 BCI 思想解码或神经科学获得进步。
