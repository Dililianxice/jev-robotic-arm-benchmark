# 频繁小步运动决策：冻结方案

本项目进行同接口 Jev/DeepSeek 比较。所有运动只发生在本地 MuJoCo。

## 问题与边界

在同样的状态表示、初始条件、选项、文字策略条件、逆运动学和物理环境中，Jev 是否比快速 DeepSeek 更稳定、更快完成抓取放置？闭环状态会随各自动作分叉，只有额外延迟探针使用完全相同的输入值。这测量提示策略执行和服务端到端表现，不测通用机器人智能、视觉识别或神经解码。知乎原文因访问失败尚未核对，不能将本实验称为该文演示的精确复现。

来源为 openroboto-ai/jev-robot-control，固定提交 7a4ed8b72c3c17d7aa790678ed9660df67c10dd3。原始源码、模型与素材只读保存在 vendor；下载清单记录 Git blob 和 SHA256。原作比较的是 Jev、GPT-4.1-mini、GPT-6 Astra，不是 DeepSeek。公开视频成功一次不代表成功率。

## 固定条件

- 原 xArm7 物理夹爪与苹果/盘子，不使用旧 UR10e 吸附约束，不替换物理、不写完整抓取技能；原场景随机种子 0/1/2 各配对一次。后两种子只改变水果初始 XY ±12 mm，独立任务多样性很有限。
- 每一循环先选 8 类意图之一，再同一次请求选择 X/Y/Z 的 negative/hold/positive 与夹爪 open/hold/close。原代码决定位移幅度、IK、伺服，模型决定方向和夹爪。
- 保留精确几何、接触、对齐和抓稳布尔字段。没有相机感知。此项目没有候选动作的前向物理预演；两组都没有，不将其他项目的预演优势混入。
- 保留原来等待 API 时暂停物理的条件、每步 0.32 秒仿真及最大 160 步。按原 success() 判定接触、盘内稳定、夹爪打开和 TCP 抬升。成功谓词以代码为准，不以模型 finish 自报为准。
- 原场景每步可进行少量毫米级运动。规则基线直接实现同一文字条件，测量这份明确策略能被程序覆盖的程度，不代表所有场景都可覆盖。
- Jev 固定 jev-1.13.0，官方 TypeSafe endpoint。DeepSeek 用 deepseek-flash、禁用 thinking、temperature=0、JSON 标签、max_tokens=150，官方 endpoint。两者都复用 requests Session。实际服务返回模型名记录下来。
- 两者接收相同的问题生成器、判据和状态表示；给定相同状态时问题与选项相同，实际闭环状态可随决策分叉；共同删除原 motor 提示里“生成概率分布”的末句。Jev 原生返回概率，DeepSeek 只生成最终标签，概率不用于控制。不复现原 OpenRouter 传输，也不强迫 DeepSeek 生成无用概率。
- 三个种子的请求组顺序依次 J/D、D/J、J/D。此有限顺序不能消除全部时段/负载混杂，不做总体显著性推广。
- 原始轨迹离线重放必须通过 1e-7 qpos 容差，再运行新 API。先运行规则检查，但不据此更改原场景或条件。

## 延迟拆解与配对探针

主实验记录每请求至响应头、完整响应体、解析结束的耗时，输入/输出字节、服务返回 token usage；不保存响应头或凭据。到响应头的耗时仍包含连接、网络、排队、推理和服务缓冲，不能叫“纯网络”或“纯推理”。headers 与 body 差值也不是生成 token 的纯耗时。

额外同状态探针固定使用原始公开 Jev 轨迹第 0/15/30/45/60/75/90/105 循环（0-based）的 before：偶数索引位置取 intent，奇数位置取 motor，motor 使用原始记录的已选 intent。全部探针在新实验结果出现前定义；重复两次，每次反转相邻 provider 顺序，16 次请求/组。共享同一机器人状态和问题，区分输入/轨迹差异与端到端差异，不以原始 Jev 动作为正确标签，不在探针上调参。不测并发吞吐，无法确定服务端内部耗时。

## 预算、停止、统计

最多 160×2×3=960 次主实验请求/组，16 次额外探针/组；硬上限 992，未使用的 16 次不是重试预算。每请求连接 10 秒、读取 30 秒上限，无自动重试。首次 API/解析失败停止该运行，不补抽成功，记录错误并报告未完成；机械任务失败仍按完整配对方案继续。文件锁、先写 ledger、禁止重复 tag 和已开局任务覆盖。旧 v1/v2 不修改。

报告所有 9 局（规则和两模型各 3），成功/失败、步数、无效动作、抓取尝试、API 次数、真实墙钟、仿真时间、纯本地物理计算时间、usage 与参考单价费用。墙钟不是实时机器人执行时间：物理加速运行且 API 等待时暂停。另给“API 等待 + 仿真时长”的串行实时估算，明确非实测硬件耗时。失败不能以较短时间宣称更快。

探索性“明显更好”操作门槛：成功率不能更低，且至少 2/3 配对成功局有 >=20% 的 API+仿真估算时间下降；或多成功 >=2/3 局。另分别报告费用变化，不用便宜替代可靠性/速度。样本过少，门槛仅决定是否值得扩展，无统计显著/一般性证明。全成功两组才汇总完整 3 对时间门槛；缺失/错误必须标记不可判定。

完成后逐局离线重放，检查 qpos/动作结果；导出 CSV、科学图、中文报告与可查看仿真视频。视频只为查看动作，注明 API 等待不在仿真视频时轴内。无真实硬件、神经数据、外部联系或自动发布。

审查补充：成功谓词实际为 TCP >=145 mm，提示 FINISH 的160 mm不是停止阈值。API失败统一写全局停止标记，之后 live/probes 均不再发请求；错误请求的耗时和 tag 计入整局。错误正文不保存。启动时核查离线重放证据与源码/原始记录哈希。
